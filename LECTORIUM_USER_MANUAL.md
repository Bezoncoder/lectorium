# Lectorium

Lectorium — закрытая учебная платформа на **FastAPI + PostgreSQL + Jinja2** для публикации лекций, просмотра видео, учёта просмотров, отображения расписания курса и прогресса студентов.

Проект поддерживает две роли:

- **student** — смотрит кабинет, расписание, каталог и записи лекций;
- **admin** — загружает/редактирует видео, ведёт расписание курса и управляет доступными учебными материалами.

> Все страницы, видео и API ниже предполагают, что пользователь авторизован, если явно не указано иное.

---

## Возможности

- Cookie-сессии и вход по логину/паролю.
- Роли `student` и `admin`.
- Каталог учебных видео.
- Просмотр локальных видео через защищённый маршрут `/media/{video_id}`.
- Учёт просмотра: лекция засчитывается после 15 секунд просмотра.
- Кабинет студента: прогресс, ближайшая лекция, расписание и ссылки на записи.
- Один редактируемый курс BootCamp.
- Админ-редактор курса: название, период, часовой пояс, Telemost, занятия и даты.
- Связь «пункт расписания → запись видео».
- Статистика просмотров и список зрителей по каждой записи.
- Alembic-миграции.

## Архитектура и модули

### API-слой: `app/api/`

Маршруты принимают HTTP-запрос, проверяют пользователя через зависимости, вызывают сервисы и возвращают HTML, redirect, JSON или видеофайл.

- `auth.py` — отображает форму входа, создаёт и удаляет cookie-сессии.
- `cabinet.py` — отдаёт главную страницу `/` с прогрессом и расписанием.
- `videos.py` — показывает каталог, страницу лекции, выдаёт поток файла и регистрирует просмотр.
- `admin.py` — защищённые админ-маршруты для видео и расписания.
- `statistics.py` — общая статистика и зрители конкретного видео.

### Сервисный слой: `app/services/`

Сервисный слой хранит прикладную логику и использует декоратор `@connection` из `app/db/session.py`. Декоратор открывает `AsyncSession`, передаёт её сервисному методу и делает rollback при исключении.

- `VideoService` создаёт, меняет и удаляет видео, а также записывает просмотры.
- `CabinetService` сопоставляет занятия с просмотренными видео, формирует статусы и вычисляет прогресс.
- `ScheduleService` изменяет общие данные курса, добавляет/редактирует/удаляет занятия и готовит данные админ-страницы.
- `SessionService` создаёт, ищет и удаляет сессии пользователя.

### DAO-слой: `app/db/dao/`

DAO выполняют SQLAlchemy-запросы. Базовый `BaseDAO` уже содержит типовые операции:

```python
add()
get_by_id()
get_one_or_none()
find_all()
update_one_by_id()
delete_by_id()
count()
```

`CourseDAO` и `ScheduleLessonDAO` дополняют их запросами, специфичными для единственного курса и расписания.

### Модели БД: `app/db/models/`

| Модель | Таблица | Назначение |
|---|---|---|
| `User` | `users` | Логин, хеш пароля, роль |
| `UserSession` | `user_sessions` | Cookie-сессии и срок действия |
| `Video` | `videos` | Метаданные загруженного ролика |
| `VideoView` | `video_views` | Факт просмотра видео пользователем за дату |
| `Course` | `courses` | Настройки единственного курса |
| `ScheduleLesson` | `schedule_lessons` | Лекция: дата, название, порядок и связанное видео |

## Логика курса и расписания

В текущей версии Lectorium есть **один общий курс**. В базе он находится в таблице `courses`.

```text
Course
  └── ScheduleLesson (много занятий)
          └── Video (необязательная запись лекции)
```

Поле `schedule_lessons.video_id` может быть пустым:

```text
video_id = NULL
```

Это означает: занятие есть в расписании, но запись ещё не добавлена или не привязана.

### Начальное расписание

Скрипт `scripts/init_bootcamp.py` создаёт один курс и стартовые занятия:

```text
1 сентября 2026, 20:00 — Онбординг
3 сентября 2026, 20:00 — #1 Python API
8 сентября 2026, 20:00 — #1.2 Github
10 сентября 2026, 20:00 — #2 API-S3
15 сентября 2026, 20:00 — #3 Spark
17 сентября 2026, 20:00 — #4 ClickHouse
```

Все эти значения можно потом менять в админ-интерфейсе.

### Что происходит при удалении видео

Связь с видео настроена как `ON DELETE SET NULL`:

```text
Админ удаляет видео
        ↓
У занятия очищается video_id
        ↓
Занятие остаётся в расписании
        ↓
Студент видит, что запись пока недоступна
```

## Логика прогресса

Прогресс считается отдельно для каждого студента.

1. У занятия расписания есть `video_id`.
2. Студент открывает страницу видео.
3. После 15 секунд браузер вызывает:

```text
POST /videos/{video_id}/view
```

4. Сервер создаёт запись в `video_views`.
5. Кабинет выбирает уникальные просмотренные `video_id` пользователя.
6. Если это видео привязано к уроку расписания, урок считается завершённым.

Формула:

\[
\text{Прогресс} =
\left\lfloor
\frac{\text{просмотренные лекции}}{\text{все лекции расписания}}
\times 100
\right\rfloor
\]

Например:

```text
Всего занятий: 6
Просмотрено: 2
Прогресс: 33%
```

### Статусы лекции в кабинете

| Условие | Статус | Что видит студент |
|---|---|---|
| Связанное видео было просмотрено | `completed` | «Лекция просмотрена», «Открыть снова» |
| `video_id` есть, но просмотра нет | `available` | «Смотреть запись» |
| Видео нет, дата ещё не наступила | `upcoming` | «Скоро» или кнопка Telemost |
| Видео нет, дата уже прошла | `pending` | «Запись появится после проведения занятия» |

Один и тот же просмотр одного ролика в разные дни не увеличивает прогресс повторно: для расчёта используются уникальные `video_id`.

# Быстрый запуск

## 1. Требования

- Python 3.12+
- PostgreSQL
- virtualenv / venv
- `ffmpeg` — необязательно, но полезно для подготовки видео
- Docker и Docker Compose — если проект запускается в контейнерах

## 2. Создание виртуального окружения

Из корня проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

## 3. Установка зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Если проект использует настройки из `pyproject.toml`, допустим альтернативный вариант:

```bash
pip install -e .
```

Настройки читаются в `app/core/config.py`. Укажите реальные значения в `.env` либо в переменных окружения.

Пример ориентировочного `.env`:

```dotenv
APP_NAME=Lectorium
DEBUG=true

DATABASE_HOST=127.0.0.1
DATABASE_PORT=5432
DATABASE_NAME=lectorium
DATABASE_USER=lectorium
DATABASE_PASSWORD=change_me

SESSION_COOKIE_NAME=lectorium_session
SESSION_TTL_DAYS=30

VIDEO_DIR=video
```

Названия переменных должны соответствовать именно вашему `app/core/config.py`. Не храните настоящий `.env` с паролями в Git.

## 5. Создание базы PostgreSQL

Пример локального создания базы и пользователя:

```bash
sudo -u postgres psql
```

Внутри `psql`:

```sql
CREATE USER lectorium WITH PASSWORD 'change_me';
CREATE DATABASE lectorium OWNER lectorium;
\q
```

Если база и PostgreSQL создаются Docker Compose, пропустите этот шаг и используйте значения из `docker-compose.yml` / env-файла.

```bash

```

Проверить применённую ревизию:

```bash

```

Проверить историю:


> Не запускайте `alembic downgrade` на рабочей базе без резервной копии.

## 7. Первичная инициализация курса

После миграций выполните:


# Инструкция для студента

## Вход

1. Откройте `/login`.
2. Введите выданные логин и пароль.
3. После успешного входа откроется кабинет `/`.

Сессия хранится в cookie. Кнопка выхода удаляет сессию и возвращает пользователя к состоянию входа.

## Кабинет

На главной странице `/` студент видит:

- название курса;
- период и часовой пояс;
- кнопку Telemost, если администратор добавил ссылку;
- процент прогресса;
- число просмотренных и оставшихся лекций;
- ближайшую будущую лекцию;
- полное расписание.

## Просмотр лекции

Если запись привязана к занятию, напротив него есть кнопка:

```text
Смотреть запись
```

Она открывает страницу видео. После 15 секунд просмотра лекция засчитывается в прогресс.

Важно:

- просмотр меньше 15 секунд не засчитывается;
- повторные просмотры одной лекции не увеличивают процент повторно;
- если запись пока не добавлена, это не ошибка: администратор опубликует её позже.

## Каталог видео

Раздел `/videos` содержит все доступные загруженные записи. В нём могут быть:

- основные лекции;
- дополнительные материалы;
- бонусные занятия;
- записи, которые администратор ещё не связал с расписанием.

Видео из каталога доступно сразу после загрузки администратором. Если студент посмотрел ролик до его привязки к уроку, а затем админ связал этот ролик с лекцией, просмотр будет засчитан автоматически.

# Инструкция для администратора

## Загрузка видео

1. Откройте `/admin/videos`.
2. Нажмите **«Добавить видео»**.
3. Укажите название и, при необходимости, описание.
4. Выберите видеофайл.
5. Нажмите **«Загрузить»**.

После загрузки:

- файл сохраняется в каталоге `video/`;
- в БД появляется строка в `videos`;
- ролик сразу доступен в `/videos` для авторизованных студентов;
- ролик ещё не влияет на прогресс, пока не привязан к занятию расписания.

## Привязка видео к лекции

1. Откройте `/admin/schedule`.
2. Найдите нужную лекцию в блоке «Занятия в расписании».
3. В поле **«Запись видео»** выберите нужный ролик.
4. Нажмите **«Сохранить»** у этой лекции.

После этого:

```text
schedule_lessons.video_id = ID выбранного видео
```

Для студента лекция меняет статус:

```text
Запись появится позже
        ↓
Запись доступна для просмотра
        ↓
Смотреть запись
```

Одна запись может быть привязана только к одному занятию. Это защищает прогресс: одно видео не сможет одновременно засчитаться как две разные лекции.

## Настройка курса

В `/admin/schedule` в карточке «Настройки курса» можно изменить:

- название курса;
- период обучения;
- часовой пояс;
- ссылку на Yandex Telemost.

Нажмите **«Сохранить курс»**. Изменения сразу отображаются в кабинете студентов.

## Управление занятиями

На `/admin/schedule` можно:

- добавить занятие: название, дату/время и, при наличии, видео;
- изменить название лекции;
- изменить дату и время;
- прикрепить или снять привязку записи видео;
- удалить отдельное занятие;
- очистить всё расписание.

### Очистка расписания

Кнопка **«Очистить расписание»** удаляет только записи таблицы `schedule_lessons`.

Она **не удаляет**:

- видеофайлы из `video/`;
- строки таблицы `videos`;
- пользователей;
- просмотры из `video_views`.

## Удаление видео

Если удалить видео через `/admin/videos`, удаляются:

- запись из таблицы `videos`;
- физический файл из каталога `video/`;
- связанные просмотры из `video_views` через `ON DELETE CASCADE`.

Связанное занятие расписания не удаляется. Его `video_id` автоматически становится `NULL`, поэтому в кабинете студент увидит, что запись временно недоступна.

# Добавление пользователя через API

## Важное текущее ограничение

В текущем приложении создание пользователей реализовано через Python-сервис и скрипты:

```python
UserService.create_student(...)
```

Но публичного HTTP-endpoint вида:

```text
POST /api/users
```

в показанной структуре **нет**.

Поэтому внешний `requests`-клиент не сможет добавить пользователя по HTTP, пока не будет добавлен закрытый admin API.

Ниже приведён рекомендуемый защищённый endpoint и пример клиента. Он создаёт только студента; администратора создавайте через CLI-скрипт, чтобы не выдавать административные права через внешний API без дополнительной защиты.

## Добавьте admin API создания студента

В `app/api/admin.py` добавьте импорт:

```python
from app.services.auth import UserService
```

И добавьте endpoint в конец файла:

```python
@router.post(
    "/api/students",
    status_code=status.HTTP_201_CREATED,
)
async def admin_create_student_api(
    _: Annotated[User, Depends(require_admin)],
    login: Annotated[str, Form(min_length=3, max_length=64)],
    password: Annotated[str, Form(min_length=8, max_length=255)],
):
    student = await UserService.create_student(
        login=login.strip(),
        password=password,
    )

    if student is None:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT,
            detail="Пользователь с таким логином уже существует",
        )

    return {
        "id": student.id,
        "login": student.login,
        "role": student.role.value,
    }
```

Этот endpoint фактически будет доступен по адресу:

```text
POST /admin/api/students
```

Он требует активную сессию администратора, потому что роутер `admin.py` использует `require_admin` в параметрах endpoint-а.

### Запрос

Формат тела — `application/x-www-form-urlencoded`, потому что endpoint использует `Form(...)`.

```http
POST /admin/api/students
Content-Type: application/x-www-form-urlencoded
Cookie: lectorium_session=...

login=student_01&password=StrongPassword123
```

### Успешный ответ

```json
{
  "id": 15,
  "login": "student_01",
  "role": "student"
}
```

### Ошибки

| Код | Причина |
|---:|---|
| `401` | Нет активной сессии администратора |
| `403` | Текущий пользователь не администратор |
| `409` | Логин уже занят |
| `422` | Логин/пароль не прошли валидацию |

> Не добавляйте пароль в URL, логи, `GET`-параметры или ответы API. Передавайте его только по HTTPS в POST-теле и никогда не возвращайте его клиенту.

# Пример Python requests: вход админа и создание студента

Создайте, например, файл `scripts/api_create_student_example.py`.

```python
from getpass import getpass

import requests


BASE_URL = "http://127.0.0.1:8000"

admin_login = input("Логин администратора: ").strip()
admin_password = getpass("Пароль администратора: ")

student_login = input("Логин нового студента: ").strip()
student_password = getpass("Пароль нового студента: ")

with requests.Session() as client:
    login_response = client.post(
        f"{BASE_URL}/login",
        data={
            "login": admin_login,
            "password": admin_password,
        },
        allow_redirects=False,
        timeout=15,
    )

    if login_response.status_code not in (200, 302, 303):
        raise SystemExit(
            "Не удалось войти: "
            f"HTTP {login_response.status_code}; "
            f"{login_response.text}"
        )

    create_response = client.post(
        f"{BASE_URL}/admin/api/students",
        data={
            "login": student_login,
            "password": student_password,
        },
        timeout=15,
    )

    if create_response.status_code == 201:
        print("Студент создан:")
        print(create_response.json())
    else:
        print(
            "Ошибка создания студента: "
            f"HTTP {create_response.status_code}"
        )
        print(create_response.text)
```

Запуск:

```bash
python -m scripts.api_create_student_example
```

Сессия `requests.Session()` сохраняет cookie, которую сервер выставляет при `POST /login`. Поэтому второй запрос автоматически выполняется как авторизованный администратор.

## Минимальный requests-вариант с заранее известными данными

Используйте его только локально для теста. Не сохраняйте реальные пароли в исходном коде.

```python
import requests


BASE_URL = "http://127.0.0.1:8000"

with requests.Session() as client:
    client.post(
        f"{BASE_URL}/login",
        data={
            "login": "admin",
            "password": "REPLACE_WITH_REAL_PASSWORD",
        },
        timeout=15,
    )

    response = client.post(
        f"{BASE_URL}/admin/api/students",
        data={
            "login": "student_01",
            "password": "StrongPassword123",
        },
        timeout=15,
    )

    response.raise_for_status()
    print(response.json())
```

# Безопасность и эксплуатация

## Пароли

- В БД хранится только `password_hash`.
- Не записывайте пароль в README, Git, `.env`, shell history, логи и API-ответы.
- Для production используйте сложные уникальные пароли и HTTPS.

## Сессии

- Cookie-сессия проверяется зависимостью `get_current_user`.
- `require_admin` дополнительно проверяет `UserRole.ADMIN`.
- При `401` HTML-запрос перенаправляется на `/login` вашим обработчиком исключений.

## Видео

- Видеофайлы лежат локально в `video/`.
- Маршрут `/media/{video_id}` требует авторизацию.
- `FileResponse(..., content_disposition_type="inline")` отдаёт файл браузеру для воспроизведения в `<video>`.
- В текущей реализации любой авторизованный пользователь может открыть любой ролик из каталога.
- Это не DRM: пользователь, который может смотреть ролик, технически может сохранить поток. Для усиленной защиты потребуется отдельная архитектура, например Nginx `X-Accel-Redirect`, S3 signed URLs или HLS.

## Резервные копии

Нужно резервировать минимум:

```text
PostgreSQL database
video/ directory
.env / секретные конфигурации — отдельно и безопасно
```

Пример дампа PostgreSQL:

```bash
pg_dump -U lectorium -d lectorium > backup_lectorium.sql
```

Пример архива видео:

```bash
tar -czf backup_video_$(date +%F).tar.gz video/
```

## Production-рекомендации

- Отключите `DEBUG`.
- Запускайте Uvicorn без `--reload`.
- Размещайте приложение за Nginx/Caddy.
- Используйте HTTPS.
- Храните `SECRET_KEY`, строку БД и пароли вне репозитория.
- Для высокой нагрузки на видео перенесите раздачу на Nginx через `X-Accel-Redirect`, объектное хранилище или CDN.
- Регулярно делайте backup БД и файлов `video/`.

# Типичные проблемы

## `/admin/schedule` отвечает «Курс не найден»

После применения миграций выполните первичную инициализацию:

```bash
python -m scripts.init_bootcamp
```

## Ошибка `422`, параметр `session` обязателен

Не применяйте декоратор `@connection` напрямую к FastAPI route handler. Он предназначен для методов сервисного слоя. Маршрут должен вызвать сервис, а сервис сам откроет `AsyncSession`.

## Видео не засчитывается в прогресс

Проверьте последовательно:

1. Студент просмотрел запись не менее 15 секунд.
2. В таблице `video_views` есть строка с `user_id` и `video_id`.
3. Администратор связал запись с пунктом расписания через `/admin/schedule`.
4. В `schedule_lessons.video_id` хранится ID нужного ролика.
5. Студент обновил страницу кабинета.

## В уроке нет кнопки «Смотреть запись»

Урок существует, но к нему не назначено видео. Откройте `/admin/schedule`, выберите запись в поле «Запись видео» и сохраните занятие.

## Ошибка уникальности при привязке видео

Одно видео может быть назначено только одному занятию. Сначала снимите его с прежней лекции или загрузите/выберите отдельную запись.

## После изменения CSS старые стили остаются

Сделайте жёсткое обновление браузера:

```text
Ctrl + Shift + R
```

Или добавьте временную версию к ссылке CSS в `base.html`:

```html
<link
  rel="stylesheet"
  href="{{ url_for('static', path='css/style.css') }}?v=2"
>
```
